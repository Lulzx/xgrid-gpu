# Technical Specification: `xgrid-gpu`
**Zero-Dependency GPU Drop-In Replacement for STELLOPT `MAKEGRID` (`xgrid`)**

**Version:** 0.1.0  
**Target Backends:** CUDA (`fp64`), Apple Metal (`ds` double-single emulation), CPU Fallback (`fp64` SIMD)  
**Implementation Language:** Zig (or C11) host + native `.cu` / `.metal` kernels  
**External Dependencies:** None (zero `libnetcdf`, `libhdf5`, `MPI`, or Python runtime)

---

## 1. Purpose & Design Goals

`xgrid-gpu` computes the 3D vacuum magnetic field $\mathbf{B}(R, \phi, Z)$ generated by filamentary stellarator/tokamak coils on a cylindrical grid and emits bit-for-bit compatible `mgrid_<ext>.nc` and `extcur.<ext>` files for downstream fusion codes (`VMEC`, `FIELDLINES`, `BEAMS3D`, `STELLOPT`).

### Non-Negotiable Constraints
1. **Single Static Binary:** Compiles to one standalone executable with zero external shared library dependencies (`libnetcdf` is replaced by a ~150-LOC native NetCDF-3 writer).
2. **Exact Drop-In Parity:** Accepts standard `coils.<ext>` filament files, `&MGRID_NLI` Fortran namelists, legacy interactive/piped 10-line stdin scripts, and modern CLI flags.
3. **Machine-Precision Accuracy:** Matches legacy Fortran `xgrid` to $L_\infty < 10^{-12}$ (CUDA `fp64`) and $L_\infty < 10^{-11}$ (Metal `ds` emulation).
4. **Target Performance:** 500x–1000x wall-clock speedup over single-core Fortran `xgrid` (e.g., NCSX `coils.c09r00`, `201 × 201 × 36`, 10 coil groups: ~400 s on CPU $\rightarrow$ < 200 ms on GPU including disk I/O).

## 2. Input Specification

### 2.1 CLI & Invocation Modes
`xgrid-gpu` supports three invocation patterns for backward compatibility with existing STELLOPT workflows:

```bash
# 1. Modern CLI flags (recommended)
xgrid-gpu --coils coils.c09r00 --mode S --sym true \
  --rmin 0.436 --rmax 2.436 --zmin -1.0 --zmax 1.0 \
  --ir 201 --jz 201 --kp 36 --out mgrid_c09r00.nc

# 2. Fortran Namelist file (&MGRID_NLI)
xgrid-gpu input_xgrid.dat

# 3. Legacy 10-line stdin pipe
xgrid-gpu < input_xgrid.dat

```

### 2.2 `&MGRID_NLI` Namelist Parameters

| Parameter | Type | Description |
| --- | --- | --- |
| `MGRID_EXT` | `string` | Suffix for `coils.<ext>`, `mgrid_<ext>.nc`, and `extcur.<ext>` |
| `MGRID_MODE` | `char` | `'S'` (Scaled to unit current per group) or `'R'` (Raw currents) |
| `LSTELL_SYM` | `bool` | `T` = enforce stellarator symmetry; `F` = full field period |
| `RMIN`, `RMAX` | `f64` | Radial grid bounds in meters |
| `ZMIN`, `ZMAX` | `f64` | Vertical grid bounds in meters |
| `IR`, `JZ`, `KP` | `i32` | Number of radial ($R$), vertical ($Z$), and toroidal ($\phi$) grid points |

### 2.3 `coils.<ext>` Filament File Format

Standard ASCII filament format:

```text
periods 3
begin filament
mirror NIL
  x0   y0   z0   I0
  x1   y1   z1   I1
  ...
  x0   y0   z0   0.0   <group_id>   <group_name>
end

```

* **Line 1:** `periods <nfp>` — number of toroidal field periods ($N_{\text{fp}}$).
* **Line 2:** `begin filament`.
* **Line 3:** Ignored header line.
* **Body:** Sequential Cartesian vertices $(x_k, y_k, z_k)$ in meters and segment current $I_k$ in Amperes.
* **Coil Termination:** A vertex with `current == 0.0` closes the filament loop and carries `<group_id>` (1-indexed integer) and `<group_name>` (ASCII string, padded/truncated to 30 bytes).
* **File Termination:** Line starting with `end`.

**Parser Output (SoA Segment Buffer):**
Each consecutive pair of vertices $(k, k+1)$ within a coil produces one straight segment:

* Start point $\mathbf{r}_i = (x_k, y_k, z_k)$
* End point $\mathbf{r}_f = (x_{k+1}, y_{k+1}, z_{k+1})$
* Segment vector $\mathbf{L} = \mathbf{r}_f - \mathbf{r}_i$, length $L = \Vert{}\mathbf{L}\Vert{}$, unit vector $\hat{\mathbf{e}} = \mathbf{L} / L$
* Effective current weight $w$:
* If `MGRID_MODE == 'R'`: $w = I_k$
* If `MGRID_MODE == 'S'`: $w = I_k / I_{\text{group}}$, where $I_{\text{group}}$ is the nominal group current recorded in `raw_coil_cur` and `extcur.<ext>`.


* Segments are sorted and partitioned contiguously by `group_id` $\in [0, N_{\text{groups}} - 1]$ to eliminate branching inside the GPU kernel.

## 3. Mathematical Formulation

### 3.1 Cylindrical Grid Definition

For $i \in [0, \text{IR}-1]$, $j \in [0, \text{JZ}-1]$, $k \in [0, \text{KP}-1]$:


$$R_i = R_{\min} + i \cdot \frac{R_{\max} - R_{\min}}{\text{IR} - 1}, \qquad Z_j = Z_{\min} + j \cdot \frac{Z_{\max} - Z_{\min}}{\text{JZ} - 1}$$

$$\phi_k = k \cdot \frac{2\pi}{N_{\text{fp}} \cdot \text{KP}}$$


Cartesian evaluation point:


$$\mathbf{r} = (R_i \cos\phi_k,\; R_i \sin\phi_k,\; Z_j)$$

### 3.2 Hanson–Hirshman Exact Straight-Segment Biot–Savart Law

For a straight wire segment from $\mathbf{r}_i$ to $\mathbf{r}_f$ with length $L = \Vert{}\mathbf{r}_f - \mathbf{r}_i\Vert{}$, unit direction $\hat{\mathbf{e}} = (\mathbf{r}_f - \mathbf{r}_i)/L$, and current $I$:

$$\mathbf{R}_i = \mathbf{r} - \mathbf{r}_i, \qquad \mathbf{R}_f = \mathbf{r} - \mathbf{r}_f$$

$$R_i = \Vert{}\mathbf{R}_i\Vert{}, \qquad R_f = \Vert{}\mathbf{R}_f\Vert{}$$

$$\mathbf{B}_{\text{seg}}(\mathbf{r}) = \frac{\mu_0 I}{4\pi} \cdot \frac{2 L (R_i + R_f)}{R_i R_f \left[(R_i + R_f)^2 - L^2\right]} \left(\hat{\mathbf{e}} \times \mathbf{R}_i\right)$$


where $\frac{\mu_0}{4\pi} = 10^{-7}\ \text{T}\cdot\text{m/A}$ (exact).

**Singularity Guard:**
If $(R_i + R_f)^2 - L^2 < \epsilon_{\text{collinear}}$ (e.g., $10^{-24}\ \text{m}^2$, point lies directly on the wire segment), skip the segment contribution ($\mathbf{B}_{\text{seg}} = \mathbf{0}$) to prevent `NaN`/`Inf`.

### 3.3 Cylindrical Projection

After accumulating Cartesian $\mathbf{B} = (B_x, B_y, B_z)$ for a coil group at $(R_i, \phi_k, Z_j)$:


$$B_R = B_x \cos\phi_k + B_y \sin\phi_k$$

$$B_\phi = -B_x \sin\phi_k + B_y \cos\phi_k$$

$$B_Z = B_z$$

### 3.4 Stellarator Symmetry (`LSTELL_SYM = T`)

When stellarator symmetry is enabled, the field satisfies:


$$B_R(R, -\phi, -Z) = -B_R(R, \phi, Z)$$

$$B_\phi(R, -\phi, -Z) = B_\phi(R, \phi, Z)$$

$$B_Z(R, -\phi, -Z) = B_Z(R, \phi, Z)$$


Only toroidal planes $k \in [0, \lfloor \text{KP}/2 \rfloor]$ are evaluated on the GPU. Remaining planes $k' = \text{KP} - k$ (for $k > 0$ and $k' < \text{KP}$) are filled by mirroring $j' = (\text{JZ} - 1) - j$ with the sign rules above, cutting compute by ~2x.

## 4. GPU Compute Architecture

### 4.1 Thread Mapping & Shared-Memory Tiling

* **Grid Topology:** 1 thread per cylindrical grid point $(i, j, k)$ in the active half-period (or full period if `LSTELL_SYM = F`).
* **Dispatch:** Launch once per coil group $g \in [0, N_{\text{groups}} - 1]$ (or 4D dispatch if total memory allows) writing directly into contiguous output buffers `br[g]`, `bp[g]`, `bz[g]` ordered as `(k, j, i)` (C-order: `rad` fastest, `zee` middle, `phi` slowest).
* **Segment Tiling:**
* Load `TILE_SIZE = 256` segments into shared/threadgroup memory per iteration (`sx, sy, sz, ex, ey, ez, L, w`).
* All threads in the block (256 threads) cooperatively load one segment each, `__syncthreads()`, accumulate the 256 Biot–Savart contributions in registers, and repeat.
* **Arithmetic Intensity:** ~30 FLOPs per segment per thread vs. 0 global memory reads inside the inner loop $\rightarrow$ **compute-bound**, saturating FMA units.



### 4.2 Precision Strategy: CUDA `fp64` vs. Metal `ds` (Double-Single)

* **CUDA Backend:** Native IEEE-754 `double` (`fp64`) throughout.
* **Apple Metal Backend:** Apple Silicon GPUs lack native `fp64` hardware. Pure `fp32` suffers catastrophic cancellation in $(R_i + R_f)^2 - L^2$ when $R_i \gg L$ (far-field) or near collinearity.
* **Solution:** Implement a lightweight `ds` (`float2`: `{hi, lo}`) library in Metal using Dekker/Knuth error-free transformations (`two_sum`, `quick_two_sum`, `two_prod` via hardware `fma(a, b, -p)`).
* Gives ~48 bits of significand (~$10^{-14}$ relative precision) at ~4x the throughput of CPU `fp64` and zero hardware dependency on `fp64` ALUs.
* Expose a `--fp32` CLI flag for rapid exploratory runs where $10^{-5}$ accuracy is acceptable.

## 5. Zero-Dependency Output Writers

### 5.1 NetCDF-3 64-Bit Offset (`CDF\x02`) Binary Writer

To eliminate `libnetcdf` and `libhdf5`, `xgrid-gpu` writes the NetCDF-3 64-bit offset format (`magic = "CDF\x02"`) directly using big-endian serialization.

#### Required Dimensions

| Name | Size |
| --- | --- |
| `stringsize` | `30` |
| `external_coil_groups` | `nextcur` |
| `dim_00001` | `1` |
| `external_coils` | `nextcur` |
| `rad` | `IR` |
| `zee` | `JZ` |
| `phi` | `KP` |

#### Required Variables

| Variable | Type | Dimensions (C-order) | Description |
| --- | --- | --- | --- |
| `ir` | `NC_INT` | scalar | Radial grid count |
| `jz` | `NC_INT` | scalar | Vertical grid count |
| `kp` | `NC_INT` | scalar | Toroidal plane count |
| `nfp` | `NC_INT` | scalar | Number of field periods |
| `nextcur` | `NC_INT` | scalar | Number of coil groups |
| `rmin`, `zmin`, `rmax`, `zmax` | `NC_DOUBLE` | scalar | Grid bounds (m) |
| `mgrid_mode` | `NC_CHAR` | `(dim_00001)` | `'S'` or `'R'` |
| `coil_group` | `NC_CHAR` | `(external_coil_groups, stringsize)` | Space-padded 30-char group names |
| `raw_coil_cur` | `NC_DOUBLE` | `(external_coils)` | Nominal current per group (A) |
| `br_001` .. `br_NNN` | `NC_DOUBLE` | `(phi, zee, rad)` | $B_R$ per coil group (T or T/A) |
| `bp_001` .. `bp_NNN` | `NC_DOUBLE` | `(phi, zee, rad)` | $B_\phi$ per coil group (T or T/A) |
| `bz_001` .. `bz_NNN` | `NC_DOUBLE` | `(phi, zee, rad)` | $B_Z$ per coil group (T or T/A) |

*Note: All NetCDF-3 multi-byte values are big-endian, and every variable's byte length is padded to a 4-byte boundary. Writing directly from a pre-allocated buffer via `pwrite` / `writev` streams a 500 MB `mgrid.nc` in < 100 ms on NVMe.*

### 5.2 `extcur.<ext>` File

Plain-text file containing the nominal current for each coil group, formatted for direct copy-paste into a `VMEC` `&INDATA` namelist:

```text
EXTCUR(01) =  1.234567890123E+05  ! ModA
EXTCUR(02) =  1.234567890123E+05  ! ModB
...

```

## 7. Verification & Benchmarking Protocol

No release is considered valid until all four gates pass:

1. **Analytical Gate (Circular Loop):**
* Generate a 10,000-segment circular loop of radius $a = 1.0\ \text{m}$, $I = 1.0\ \text{A}$.
* Verify on-axis $B_Z(0, z) = \frac{\mu_0 I a^2}{2(a^2 + z^2)^{3/2}}$ to $< 10^{-11}$ relative error.


2. **Parity Gate (Fortran `xgrid` Ground Truth):**
* Run legacy STELLOPT `xgrid` on public `coils.c09r00` (NCSX) and `coils.w7x` (W7-X).
* Diff `mgrid_*.nc` against `xgrid-gpu` output:
* Metadata & dimensions: exact match.
* `br_*`, `bp_*`, `bz_*`: $\max |B_{\text{gpu}} - B_{\text{fortran}}| < 10^{-12}\ \text{T}$ (CUDA) and $< 10^{-11}\ \text{T}$ (Metal `ds`).




3. **Downstream Integration Gate:**
* Load the generated `mgrid_*.nc` directly into `VMEC` (free-boundary run) and `FIELDLINES` with zero warnings or format errors.


4. **Performance Benchmark Table (Published in README):**
* Report end-to-end wall-clock time (parse + compute + NetCDF write) across:
* Legacy Fortran `xgrid` (1 core & 16-core MPI)
* `SIMSOPT` / `DESC` (including Python/JAX cold-start)
* `xgrid-gpu` on Apple M4 Pro (Metal `ds` & `fp32`)
* `xgrid-gpu` on NVIDIA RTX 4090 / H100 (CUDA `fp64`)
